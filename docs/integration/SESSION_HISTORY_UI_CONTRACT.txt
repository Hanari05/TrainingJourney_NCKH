SESSION HISTORY / RESULTS UI — implemented local + MongoDB contract
Updated 2026-11-01 in the current backend project.

This supersedes the 2026-10-23 proposal in the old FE project. It documents
the implementation now present in this checkout; it is not a claim that
the Python camera WebSocket emits full session summaries or that the BE
team has independently approved an external API version.

OWNERSHIP / ROUTE
Camera BE sends tracking + exercise events. Godot ExerciseSession owns
session totals, targets, state timers and end status. Global saves locally;
report_sync sends merged profiles including sessions to MongoDB bridge.
MongoDB persists patient_profiles.sessions and exercise_sessions.
Results use session_completed(summary), never the last history item.
History filters patient_id. profile_id remains a display-only legacy alias;
unassigned old records are retained, never assigned to all patients.

CURRENT FIELDS
summary_schema_version: 2 for newly generated summaries.
patient_id: non-empty string, captured at session start; canonical owner.
patient_name: name snapshot captured at session start.
session_id: unique string for deduplication.
status: completed | stopped_early | interrupted.
started_at_utc, ended_at_utc: UTC datetime strings.
completed_at_utc: only present for completed sessions; legacy time fallback.
active_seconds, rest_seconds, paused_seconds, tracking_lost_seconds:
  finite, non-negative numbers in seconds, mutually exclusive categories.
  duration_source=godot_state_timer. Active excludes rest/pause/tracking loss,
  but includes waiting for the action zone while the session is active.
  Priority when states overlap: explicit menu pause > tracking loss > rest
  > active. Timers stop at session end. Not inferred from per-rep duration.
completed_reps, target_reps, completed_sets, target_sets:
  non-negative integers; targets_source=godot_session_config.
  Reps are totals across all configured sets, not just the current set.
  phase_count alone is not proof of completed sets.
valid_reps, rejected_reps: existing independent counters.
calibration_rom_angle: saved calibration snapshot, not a fresh in-session
  ROM measurement; current T-pose backend uses a normalized game index.

MISSING / LEGACY DATA
No migration or fabricated values. Missing/null/negative/non-finite numbers
display unavailable; explicit zero displays zero. Fractional rep/set counts
are invalid. Detail panels keep unavailable duration/target fields visible.
Existing old completion timestamps can be labelled legacy completed records;
new records always use their explicit status.

END STATES / LIMITS
Normal completion stores completed and emits results. Controlled scene exit
or user cancellation stores stopped_early; other stop_session reasons store
interrupted. Temporary tracking/connection loss pauses measurement in the
tracking_lost category; it does not end a session by itself.
Force kill/crash has no active-session checkpoint; no interrupted record is
guaranteed in that case. Do not claim crash recovery or exactly measured
wall-clock duration through OS suspension.
UI profile filters are not authentication. Server authorization, account
login and medical validation remain separate work, not implemented here.
Real MongoDB Atlas round-trip still requires validation in BE's environment;
automated tests use fake storage/transport and --no-save.
